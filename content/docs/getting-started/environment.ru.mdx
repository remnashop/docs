<Section title="Основные" description="Домен, шифрование и доступ" icon="Settings">

| Переменная            | Обязательная | По умолчанию            | Описание                                                                                                                            |
| --------------------- | :----------: | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `APP_DOMAIN`          | <Yes />      | —                       | Домен Remnashop без HTTP/HTTPS и без завершающего слеша. На нём открывается панель управления; из него же строятся адреса вебхуков Telegram и платёжных систем и OAuth-редиректов.                                                      |
| `APP_CRYPT_KEY`       | <Yes />      | —                       | Ключ Fernet для шифрования конфиденциальных данных в БД. Сгенерируйте: `openssl rand -base64 32`. Сохраните копию вне сервера и не меняйте после первого запуска: перестанут работать пароли администраторов, не расшифруются токен бота, ключи платёжных шлюзов и OAuth, а старые бэкапы не пройдут проверку при восстановлении. |
| `APP_JWT_SECRET`      | <Yes />      | —                       | Секрет для подписи JWT. Не короче 32 символов. Сгенерируйте: `openssl rand -base64 48`. Не используйте здесь `APP_CRYPT_KEY`.       |
| `APP_METRICS_ENABLED` | <No />       | `false`                 | Включить метрики Prometheus у процессов api и worker.                                                                               |
| `APP_ORIGINS`         | <No />       | —                       | Список разрешённых CORS-источников через запятую.                                                                                   |
| `APP_SECURE_COOKIES`  | <No />       | `true`                  | Требовать HTTPS для cookie сессии. `false` — только для локальной разработки по HTTP.                                               |
| `APP_WEB_CABINET_URL` | <No />       | —                       | Публичный URL веб-кабинета. Пример: `https://cabinet.example.com`                                                                   |

</Section>

<Section title="Remnawave" description="Подключение к панели" icon="Server">

| Переменная                   | Обязательная | По умолчанию            | Описание                                                                                                                                        |
| ---------------------------- | :----------: | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `REMNAWAVE_TOKEN`            | <Yes />      | —                       | API-токен Remnawave. Создаётся в панели: Настройки → API Токены.                                                                                |
| `REMNAWAVE_WEBHOOK_SECRET`   | <Yes />      | —                       | Секретный токен для верификации вебхуков от Remnawave. Должен совпадать с `WEBHOOK_SECRET_HEADER` в `.env` панели.                              |
| `REMNAWAVE_HOST`             | <No />       | `http://remnawave:3000` | Хост, имя Docker-сервиса или полный URL API Remnawave. Без схемы для домена подставляется `https://`, для остального — `http://` и порт `3000`. |
| `REMNAWAVE_CADDY_TOKEN`      | <No />       | —                       | Токен для аутентификации через Caddy.                                                                                                           |
| `REMNAWAVE_COOKIE`           | <No />       | —                       | Cookie для запросов в формате `key=value`.                                                                                                      |
| `REMNAWAVE_CF_CLIENT_ID`     | <No />       | —                       | Cloudflare Access Client ID.                                                                                                                    |
| `REMNAWAVE_CF_CLIENT_SECRET` | <No />       | —                       | Cloudflare Access Client Secret.                                                                                                                |

</Section>

<Section title="База данных" description="PostgreSQL и пул соединений" icon="Database">

| Переменная                                | Обязательная | По умолчанию   | Описание                                                      |
| ----------------------------------------- | :----------: | -------------- | ------------------------------------------------------------- |
| `DATABASE_PASSWORD`                       | <Yes />      | —              | Пароль для подключения к PostgreSQL.                          |
| `DATABASE_HOST`                           | <No />       | `remnashop-db` | Хост базы данных.                                             |
| `DATABASE_PORT`                           | <No />       | `5432`         | Порт базы данных.                                             |
| `DATABASE_NAME`                           | <No />       | `remnashop`    | Название базы данных.                                         |
| `DATABASE_USER`                           | <No />       | `remnashop`    | Пользователь базы данных.                                     |
| `DATABASE_POOL_SIZE`                      | <No />       | `10`           | Размер пула соединений.                                       |
| `DATABASE_MAX_OVERFLOW`                   | <No />       | `20`           | Максимум дополнительных соединений сверх пула.                |
| `DATABASE_POOL_TIMEOUT`                   | <No />       | `30`           | Таймаут ожидания соединения из пула (сек).                    |
| `DATABASE_POOL_RECYCLE`                   | <No />       | `1800`         | Время жизни соединения в пуле (сек).                          |
| `DATABASE_ECHO`                           | <No />       | `false`        | Логировать SQL-запросы.                                       |
| `DATABASE_ECHO_POOL`                      | <No />       | `false`        | Логировать события пула соединений.                           |
| `DATABASE_STATEMENT_TIMEOUT_MS`           | <No />       | `60000`        | Таймаут выполнения запроса на стороне PostgreSQL (мс).        |
| `DATABASE_IDLE_IN_TRANSACTION_TIMEOUT_MS` | <No />       | `300000`       | Таймаут простоя внутри транзакции на стороне PostgreSQL (мс). |
| `DATABASE_COMMAND_TIMEOUT_S`              | <No />       | `30`           | Таймаут команды в драйвере asyncpg (сек).                     |
| `DATABASE_CONNECT_TIMEOUT_S`              | <No />       | `10`           | Таймаут подключения в драйвере asyncpg (сек).                 |

</Section>

<Section title="Логирование" description="Уровень, ротация и хранение" icon="ScrollText">

| Переменная        | Обязательная | По умолчанию | Описание                                                              |
| ----------------- | :----------: | ------------ | --------------------------------------------------------------------- |
| `LOG_TO_FILE`     | <No />       | `true`       | Записывать логи в файл.                                               |
| `LOG_LEVEL`       | <No />       | `DEBUG`      | Уровень логирования: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`. |
| `LOG_ROTATION`    | <No />       | `100MB`      | Условие ротации лог-файла. Пример: `100MB` или `00:00`.               |
| `LOG_COMPRESSION` | <No />       | `zip`        | Формат сжатия архивных логов.                                         |
| `LOG_RETENTION`   | <No />       | `3 days`     | Срок хранения архивных логов.                                         |

</Section>
