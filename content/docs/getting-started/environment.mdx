<Section title="General" description="Domain, encryption and access" icon="Settings">

| Variable              | Required | Default                 | Description                                                                                                                               |
| --------------------- | :------: | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `APP_DOMAIN`          | <Yes />  | —                       | Remnashop domain without HTTP/HTTPS and without trailing slash. The dashboard is served on it, and it is the base for Telegram and payment webhook URLs and OAuth redirects.                                                              |
| `APP_CRYPT_KEY`       | <Yes />  | —                       | Fernet key for encrypting sensitive data in the database. Generate with `openssl rand -base64 32`. Keep a copy off the server and never change it after the first start: admin passwords stop working, the bot token, payment gateway keys and OAuth secrets can no longer be decrypted, and old backups fail the check on restore. |
| `APP_JWT_SECRET`      | <Yes />  | —                       | Secret for signing JWTs. At least 32 characters. Generate with `openssl rand -base64 48`. Do not reuse `APP_CRYPT_KEY` here.              |
| `APP_METRICS_ENABLED` | <No />   | `false`                 | Enable Prometheus metrics on the api and worker processes.                                                                                |
| `APP_ORIGINS`         | <No />   | —                       | Comma-separated list of allowed CORS origins.                                                                                             |
| `APP_SECURE_COOKIES`  | <No />   | `true`                  | Require HTTPS for session cookies. Set `false` only for local development over HTTP.                                                      |
| `APP_WEB_CABINET_URL` | <No />   | —                       | Public URL of the web cabinet. Example: `https://cabinet.example.com`                                                                     |

</Section>

<Section title="Remnawave" description="Connecting to the panel" icon="Server">

| Variable                     | Required | Default                 | Description                                                                                                                                      |
| ---------------------------- | :------: | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `REMNAWAVE_TOKEN`            | <Yes />  | —                       | Remnawave API token. Created in the panel: Settings → API Tokens.                                                                                |
| `REMNAWAVE_WEBHOOK_SECRET`   | <Yes />  | —                       | Secret token for verifying webhooks from Remnawave. Must match `WEBHOOK_SECRET_HEADER` in the panel's `.env`.                                    |
| `REMNAWAVE_HOST`             | <No />   | `http://remnawave:3000` | Host, Docker service name or full URL of the Remnawave API. Without a scheme, a domain gets `https://`, anything else `http://` and port `3000`. |
| `REMNAWAVE_CADDY_TOKEN`      | <No />   | —                       | Token for authentication via Caddy.                                                                                                              |
| `REMNAWAVE_COOKIE`           | <No />   | —                       | Cookie for requests in `key=value` format.                                                                                                       |
| `REMNAWAVE_CF_CLIENT_ID`     | <No />   | —                       | Cloudflare Access Client ID.                                                                                                                     |
| `REMNAWAVE_CF_CLIENT_SECRET` | <No />   | —                       | Cloudflare Access Client Secret.                                                                                                                 |

</Section>

<Section title="Database" description="PostgreSQL and the connection pool" icon="Database">

| Variable                                  | Required | Default        | Description                                               |
| ----------------------------------------- | :------: | -------------- | --------------------------------------------------------- |
| `DATABASE_PASSWORD`                       | <Yes />  | —              | Password for connecting to PostgreSQL.                    |
| `DATABASE_HOST`                           | <No />   | `remnashop-db` | Database host.                                            |
| `DATABASE_PORT`                           | <No />   | `5432`         | Database port.                                            |
| `DATABASE_NAME`                           | <No />   | `remnashop`    | Database name.                                            |
| `DATABASE_USER`                           | <No />   | `remnashop`    | Database user.                                            |
| `DATABASE_POOL_SIZE`                      | <No />   | `10`           | Connection pool size.                                     |
| `DATABASE_MAX_OVERFLOW`                   | <No />   | `20`           | Maximum additional connections beyond the pool.           |
| `DATABASE_POOL_TIMEOUT`                   | <No />   | `30`           | Timeout for waiting for a connection from the pool (sec). |
| `DATABASE_POOL_RECYCLE`                   | <No />   | `1800`         | Connection lifetime in the pool (sec).                    |
| `DATABASE_ECHO`                           | <No />   | `false`        | Log SQL queries.                                          |
| `DATABASE_ECHO_POOL`                      | <No />   | `false`        | Log connection pool events.                               |
| `DATABASE_STATEMENT_TIMEOUT_MS`           | <No />   | `60000`        | Statement timeout enforced by PostgreSQL (ms).            |
| `DATABASE_IDLE_IN_TRANSACTION_TIMEOUT_MS` | <No />   | `300000`       | Idle-in-transaction timeout enforced by PostgreSQL (ms).  |
| `DATABASE_COMMAND_TIMEOUT_S`              | <No />   | `30`           | Command timeout in the asyncpg driver (sec).              |
| `DATABASE_CONNECT_TIMEOUT_S`              | <No />   | `10`           | Connect timeout in the asyncpg driver (sec).              |

</Section>

<Section title="Logging" description="Level, rotation and retention" icon="ScrollText">

| Variable          | Required | Default  | Description                                                 |
| ----------------- | :------: | -------- | ----------------------------------------------------------- |
| `LOG_TO_FILE`     | <No />   | `true`   | Write logs to file.                                         |
| `LOG_LEVEL`       | <No />   | `DEBUG`  | Log level: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`. |
| `LOG_ROTATION`    | <No />   | `100MB`  | Log file rotation condition. Example: `100MB` or `00:00`.   |
| `LOG_COMPRESSION` | <No />   | `zip`    | Compression format for archived logs.                       |
| `LOG_RETENTION`   | <No />   | `3 days` | Retention period for archived logs.                         |

</Section>
