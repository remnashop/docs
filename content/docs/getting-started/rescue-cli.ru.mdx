---
title: Консоль восстановления
icon: LifeBuoy
---

Консоль восстановления возвращает доступ к панели управления, когда войти в неё уже нельзя: вход по паролю выключен, владельца не пускает список разрешённых IP, пароль утерян или сменился `APP_CRYPT_KEY`. Она запускается на сервере и не требует входа в панель.

<Section title="Запуск" description="Отдельный контейнер только с меню" icon="Terminal">

```bash title="Открыть консоль восстановления"
cd /opt/remnashop && docker compose run --rm remnashop cli
```

Команда поднимает одноразовый контейнер рядом с работающими и удаляет его после выхода. Миграции и проверка `APP_CRYPT_KEY` в нём не запускаются, поэтому консоль работает, даже если контейнер `remnashop` перезапускается по кругу.

</Section>

<Section title="Действия" description="Что делает каждый пункт меню" icon="ListChecks">

| Пункт | Действие | Когда нужно |
| ----- | -------- | ----------- |
| 1 | Enable password authentication | Вход по паролю выключили в панели, а другие способы входа не работают. |
| 2 | Restore backup | Восстанавливает базу из дампа в папке резервных копий или по указанному пути. Остальные подключения к базе обрываются, текущая база перезаписывается. |
| 3 | Reset owner access | Владельцу выдаётся новый сгенерированный пароль, список разрешённых IP очищается, все сессии завершаются, ключи доступа, привязанные OAuth-аккаунты и Telegram удаляются. API-токены остаются. Вход по паролю включается. |
| 4 | Reset encrypted secrets | `APP_CRYPT_KEY` не подходит к базе. Стирает токен и прокси бота, ключи платёжных шлюзов (шлюзы выключаются), OAuth-клиенты, пароли SMTP, секрет капчи и ключи веб-пушей. |

Каждое действие записывается в журнал событий.

</Section>

<Section title="Сменился APP_CRYPT_KEY" description="Контейнеры не запускаются" icon="KeyRound">

Если `APP_CRYPT_KEY` не совпадает с тем, с которым создавалась база, контейнеры останавливаются при старте с ошибкой `APP_CRYPT_KEY does not decrypt ...`.

<Callout type="idea">
Лучший выход — вернуть старый ключ в `.env`: ничего не потеряется.
</Callout>

Если старого ключа нет:

1. Откройте консоль восстановления и выберите **4. Reset encrypted secrets**.
2. Откройте её снова и выберите **3. Reset owner access** — пароли сотрудников завязаны на тот же ключ. Сохраните новый пароль.
3. Перезапустите: `docker compose up -d`.
4. Войдите в панель и заново введите токен бота, ключи платёжных шлюзов, настройки OAuth и SMTP.

<Callout type="warn">
Резервные копии, сделанные со старым ключом, с новым не восстановятся.
</Callout>

</Section>
