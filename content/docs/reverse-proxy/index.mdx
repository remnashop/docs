Remnashop is reached through a reverse proxy: it terminates TLS for your domain and forwards requests to the Remnashop containers.

<Callout type="warn">
Remnashop and its components cannot be served on a sub-path, such as `location /remnashop` or `location /remnawave`.
</Callout>

<Callout type="error">
SSH port forwarding is not supported. Use one of the reverse proxies below.
</Callout>

<Callout type="idea">
You need a registered domain name to continue.
</Callout>

<Section title="Where the proxy points" description="Routes for the APP_DOMAIN domain" icon="Split">

Remnashop takes requests in two containers. Telegram webhooks go to the bot container, everything else to the main container:

| Path               | Container                 | Serves                                                   |
| ------------------ | ------------------------- | -------------------------------------------------------- |
| `/api/v1/telegram` | `remnashop-telegram:5001` | Telegram webhooks                                        |
| `/`                | `remnashop:5000`      | Dashboard, API, payment and Remnawave webhooks           |

<Callout type="idea">
The `remnashop` and `remnashop-telegram` names resolve only inside the Docker network. If the proxy does not run in Docker, use `127.0.0.1:5000` and `127.0.0.1:5001`.
</Callout>

<Callout type="warn" title="Coming from 0.x?">
In the old version every request went to `remnashop:5000`. Keep that route and add `/api/v1/telegram` → `remnashop-telegram:5001`, otherwise the bot gets no messages. In 0.7–0.8 port `5001` was the database — drop it from the old rules if it was there. The full move is described in [updating](/docs/getting-started/updating).
</Callout>

</Section>
