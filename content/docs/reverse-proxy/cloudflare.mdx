---
title: Cloudflare
icon: Cloud
---

When the Remnashop or web cabinet domains are proxied through Cloudflare (orange cloud), the reverse proxy sees Cloudflare's address instead of the client's. Remnashop takes the client IP from the reverse proxy, so without the setup below every client gets a Cloudflare address: they share rate limits, and IP allowlists stop working.

<Callout type="idea">
With the grey cloud (DNS only) you don't need this.
</Callout>

<Callout type="warn">
Set this up for both domains, Remnashop and the cabinet: the cabinet passes Remnashop the address it got from the reverse proxy.
</Callout>

<Section title="How it works" description="Trusting the CF-Connecting-IP header" icon="Route">

Cloudflare sends the client address in the `CF-Connecting-IP` header. The reverse proxy should take the address from that header, but only for requests coming from Cloudflare's addresses: otherwise any client reaching the server directly could put someone else's IP in the header.

The configurations below list Cloudflare's ranges as of writing. Current lists: [IPv4](https://www.cloudflare.com/ips-v4) and [IPv6](https://www.cloudflare.com/ips-v6).

</Section>

<Section title="Caddy" description="trusted_proxies and client_ip_headers" icon="Server">

Add a global options block at the very top of the Caddyfile:

```text title="Caddyfile"
{
	servers {
		trusted_proxies static 173.245.48.0/20 103.21.244.0/22 103.22.200.0/22 103.31.4.0/22 141.101.64.0/18 108.162.192.0/18 190.93.240.0/20 188.114.96.0/20 197.234.240.0/22 198.41.128.0/17 162.158.0.0/15 104.16.0.0/13 104.24.0.0/14 172.64.0.0/13 131.0.72.0/22 2400:cb00::/32 2606:4700::/32 2803:f800::/32 2405:b500::/32 2405:8100::/32 2a06:98c0::/29 2c0f:f248::/32
		client_ip_headers CF-Connecting-IP
	}
}
```

<Callout type="warn">
If the Caddyfile already has a global options block (`{ ... }` at the top of the file), add `servers` to it instead of a second block.
</Callout>

Then add `header_up X-Forwarded-For {client_ip}` to every `reverse_proxy` of the Remnashop and cabinet sites:

```text title="Caddyfile"
https://SHOP_DOMAIN {
        encode
        handle /api/v1/telegram {
                reverse_proxy http://remnashop-telegram:5001 {
                        header_up X-Forwarded-For {client_ip}
                }
        }
        handle {
                reverse_proxy http://remnashop:5000 {
                        header_up X-Forwarded-For {client_ip}
                }
        }
}
https://CABINET_DOMAIN {
        encode
        reverse_proxy http://remnashop-cabinet:80 {
                header_up X-Forwarded-For {client_ip}
        }
}
```

<Callout type="idea">
Without `header_up`, Caddy appends Cloudflare's address to the end of `X-Forwarded-For`, and Remnashop reads exactly the last address.
</Callout>

</Section>

<Section title="Nginx" description="The real_ip module" icon="Server">

Add to the top of `nginx.conf`, next to the `upstream` blocks:

```nginx title="nginx.conf"
# Cloudflare: the client address from CF-Connecting-IP, only from Cloudflare's addresses
set_real_ip_from 173.245.48.0/20;
set_real_ip_from 103.21.244.0/22;
set_real_ip_from 103.22.200.0/22;
set_real_ip_from 103.31.4.0/22;
set_real_ip_from 141.101.64.0/18;
set_real_ip_from 108.162.192.0/18;
set_real_ip_from 190.93.240.0/20;
set_real_ip_from 188.114.96.0/20;
set_real_ip_from 197.234.240.0/22;
set_real_ip_from 198.41.128.0/17;
set_real_ip_from 162.158.0.0/15;
set_real_ip_from 104.16.0.0/13;
set_real_ip_from 104.24.0.0/14;
set_real_ip_from 172.64.0.0/13;
set_real_ip_from 131.0.72.0/22;
set_real_ip_from 2400:cb00::/32;
set_real_ip_from 2606:4700::/32;
set_real_ip_from 2803:f800::/32;
set_real_ip_from 2405:b500::/32;
set_real_ip_from 2405:8100::/32;
set_real_ip_from 2a06:98c0::/29;
set_real_ip_from 2c0f:f248::/32;
real_ip_header CF-Connecting-IP;
```

Nothing else needs to change: `X-Real-IP $remote_addr` and `X-Forwarded-For $proxy_add_x_forwarded_for` in the Remnashop and cabinet configuration already carry the corrected address.

</Section>

<Section title="Traefik" description="No built-in support" icon="Server">

<Callout type="warn">
Traefik can't take the client address from `CF-Connecting-IP`. With `forwardedHeaders.trustedIPs` it keeps the incoming `X-Forwarded-For` but appends Cloudflare's address to the end, and Remnashop reads exactly the last address.
</Callout>

If your domains are proxied through Cloudflare, use Caddy or Nginx. The other option is a third-party Traefik plugin that rewrites `X-Forwarded-For` from `CF-Connecting-IP`; such plugins don't ship with Traefik, and we haven't tested them.

</Section>

<Section title="Check" description="The client address in Remnashop" icon="CircleCheck">

Restart the reverse proxy and check the address Remnashop and the cabinet see. You can look up your own IP at, for example, [ifconfig.me](https://ifconfig.me).

**Remnashop.** Open the API documentation from the dashboard and find the `Docs access granted to IP` line in the log:

```bash title="Remnashop log"
cd /opt/remnashop && docker compose logs remnashop | grep "Docs access"
```

**Cabinet.** Open the cabinet in a browser and look at the first address in the access log lines:

```bash title="Cabinet log"
cd /opt/remnashop/cabinet && docker compose logs --tail 5
```

Both should show your IP, not an address from Cloudflare's ranges.

</Section>
