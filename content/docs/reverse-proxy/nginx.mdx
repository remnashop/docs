title: Nginx

---

In this guide we will use Nginx as a reverse proxy to reach Remnashop. We will point a domain name at the server, issue an SSL certificate and configure Nginx.

<Callout type="warn">
You need a registered domain name to continue.
</Callout>

<Section title="Installation method" description="Where Remnashop runs relative to the Remnawave panel" icon="Split">

<MethodSwitch same="Same server" separate="Separate servers" />

<Method only="same">

Nginx runs on the same server as the Remnawave panel.

<Callout type="error">
Nginx must already be installed and configured on the server that runs the Remnawave panel and the other components.
</Callout>

</Method>

<Method only="separate">

Remnashop runs on its own server, without the Remnawave panel next to it. Nginx goes on that same server.

<Callout type="error">
No other reverse proxy may be installed on this server.
</Callout>

</Method>

</Section>

<Section title="Point your domain to the server" description="An A record for the Remnashop domain" icon="Globe">

Check your server's IP address. A static IPv4 address works best.

Now point your domain name at that address, for example `shop.domain.com` → `127.0.0.1`. You can do it through a DNS provider (Cloudflare, Google Cloud and the like) or through your registrar (Namecheap and the like).

With Cloudflare you add an A record for IPv4 or an AAAA record for IPv6. Log in to [your Cloudflare account](https://dash.cloudflare.com/login) and pick the domain. In the left column open `DNS`, then `Records`, and click `Create record`.

Set `Type` to `A` and `Name` to `@`.

<Callout type="idea">
For a subdomain, put its name — `shop`, for instance — in the `Name` field instead.
</Callout>

Enter your server's IP address in the `IPv4 address` field and click `Save`. DNS records take a while to propagate.

<Callout type="idea">
The yellow cloud (domain proxied through Cloudflare) and the grey cloud (domain not proxied) behave differently. If Cloudflare works well in your region, proxying through it is the better choice.
</Callout>

![Cloudflare DNS records](/images/cloudflare-dns.webp)

Other DNS providers look different, but the process is the same.

</Section>

<Section title="Issue a certificate" description="An SSL certificate for the Remnashop domain" icon="ShieldCheck">

<Method only="same">

Issue a certificate for the Remnashop domain:

```bash title="Issue the certificate"
acme.sh --issue --standalone -d 'SHOP_DOMAIN' --key-file /opt/remnawave/nginx/shopdomain_privkey.key --fullchain-file /opt/remnawave/nginx/shopdomain_fullchain.pem --alpn --tlsport 8443
```

</Method>

<Method only="separate">

The simplest way is [acme.sh](https://acme.sh/). Install the dependencies first:

```bash title="Install dependencies"
sudo apt-get install cron socat
```

<Callout type="idea">
Any email address works for issuing a certificate, but a real one is better.
</Callout>

Replace `EMAIL` with your address:

```bash title="Install acme.sh"
curl https://get.acme.sh | sh -s email=EMAIL && source ~/.bashrc
```

Create a directory for the certificates:

```bash title="Create the directory"
mkdir -p /opt/remnashop/nginx && cd /opt/remnashop/nginx
```

<Callout type="warn">
Do not use the `.ru`, `.su` and `.рф` zones — ZeroSSL does not support them.
</Callout>

```bash title="Issue the certificate"
acme.sh --issue --standalone -d 'SHOP_DOMAIN' --key-file /opt/remnashop/nginx/shopdomain_privkey.key --fullchain-file /opt/remnashop/nginx/shopdomain_fullchain.pem --alpn --tlsport 8443
```

<Callout type="idea">
Make sure port `8443` is open on the server — it is needed to issue the certificate.
</Callout>

![Certificate issued successfully](/images/issue-cert.webp)

Output like this means the certificate is issued. `acme.sh` renews it automatically every 60 days — just keep port 8443 open and free.

</Method>

<Callout type="warn">
Replace `SHOP_DOMAIN` with the Remnashop domain — the `APP_DOMAIN` value.
</Callout>

</Section>

<Section title="Configure Nginx" description="Routes to the Remnashop containers" icon="FileCode">

<Method only="same">

With Nginx already configured, you only add new blocks to the configuration file:

```bash title="Edit nginx.conf"
cd /opt/remnawave/nginx && nano nginx.conf
```

<Callout type="error">
Do not replace the existing configuration — only add the Remnashop blocks to it.
</Callout>

Add the Remnashop upstream blocks at the top of the file:

```nginx title="nginx.conf"
upstream remnawave {
    server remnawave:3000;
}

upstream remnawave-subscription-page {
    server remnawave-subscription-page:3010;
}

upstream remnashop {
    server remnashop:5000;
}

upstream remnashop-telegram {
    server remnashop-telegram:5001;
}
```

Then add a new server block at the end of the file:

```nginx title="nginx.conf"
server {
    server_name SHOP_DOMAIN;

    listen 443 ssl;
    listen [::]:443 ssl;
    http2 on;

    # request body limit: broadcast media goes up to 50 MB
    client_max_body_size 64m;

    location = /api/v1/telegram {
        proxy_pass http://remnashop-telegram;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Port $server_port;

        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    location = /metrics {
        return 404;
    }

    location / {
        proxy_pass http://remnashop;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Port $server_port;

        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # SSL Configuration (Mozilla Intermediate Guidelines)
    ssl_protocols          TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305:DHE-RSA-AES128-GCM-SHA256:DHE-RSA-AES256-GCM-SHA384:DHE-RSA-CHACHA20-POLY1305;

    ssl_session_timeout 1d;
    ssl_session_cache shared:MozSSL:10m;
    ssl_session_tickets    off;
    ssl_certificate "/etc/nginx/ssl/shopdomain_fullchain.pem";
    ssl_certificate_key "/etc/nginx/ssl/shopdomain_privkey.key";
    ssl_trusted_certificate "/etc/nginx/ssl/shopdomain_fullchain.pem";

    ssl_stapling           on;
    ssl_stapling_verify    on;
    resolver               1.1.1.1 1.0.0.1 8.8.8.8 8.8.4.4 208.67.222.222 208.67.220.220 valid=60s;
    resolver_timeout       2s;

    # Gzip Compression
    gzip on;
    gzip_vary on;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_buffers 16 8k;
    gzip_http_version 1.1;
    gzip_min_length 256;
    gzip_types
        application/atom+xml
        application/geo+json
        application/javascript
        application/x-javascript
        application/json
        application/ld+json
        application/manifest+json
        application/rdf+xml
        application/rss+xml
        application/xhtml+xml
        application/xml
        application/wasm
        font/eot
        font/otf
        font/ttf
        image/svg+xml
        text/css
        text/javascript
        text/plain
        text/xml;
}
```

</Method>

<Section title="Start Nginx" description="Applying the configuration" icon="Play">

<Method only="same">

Mount the new certificate files in the Nginx `docker-compose.yml`:

```bash title="Edit docker-compose.yml"
cd /opt/remnawave/nginx && nano docker-compose.yml
```

```yaml title="docker-compose.yml"
services:
    remnawave-nginx:
        image: nginx:1.30
        container_name: remnawave-nginx
        hostname: remnawave-nginx
        volumes:
            - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
            - ./fullchain.pem:/etc/nginx/ssl/fullchain.pem:ro
            - ./privkey.key:/etc/nginx/ssl/privkey.key:ro
            - ./shopdomain_fullchain.pem:/etc/nginx/ssl/shopdomain_fullchain.pem:ro
            - ./shopdomain_privkey.key:/etc/nginx/ssl/shopdomain_privkey.key:ro
        restart: always
        ports:
            - '0.0.0.0:443:443'
        networks:
            - remnawave-network

networks:
    remnawave-network:
        name: remnawave-network
        driver: bridge
        external: true
```

```bash title="Restart the Nginx container"
docker compose down && docker compose up -d && docker compose logs -f
```

So Nginx picks up the new certificate after each automatic renewal, give `acme.sh` the reload command:

```bash title="Certificate auto-renewal"
acme.sh --install-cert -d 'SHOP_DOMAIN' --key-file /opt/remnawave/nginx/shopdomain_privkey.key --fullchain-file /opt/remnawave/nginx/shopdomain_fullchain.pem --reloadcmd "docker exec remnawave-nginx nginx -s reload"
```

<Callout type="idea">
`acme.sh` remembers this command and runs it after every renewal.
</Callout>

</Method>
