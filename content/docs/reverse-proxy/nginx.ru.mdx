В этом руководстве мы используем Nginx в качестве обратного прокси для доступа к Remnashop. Мы направим доменное имя на сервер, выпустим SSL-сертификат и настроим Nginx.

<Callout type="warn">
Для продолжения вам необходимо иметь зарегистрированное доменное имя.
</Callout>

<Callout type="error" title="Nginx до 1.30.7 уязвим">
Уязвимости CVE-2026-123007 и CVE-2026-123633 в HTTP/2 позволяют выполнить код на сервере запросом без авторизации. Проверьте версию командой `docker exec remnawave-nginx nginx -v` (или `nginx` для отдельного сервера) и обновитесь до 1.30.7 или 1.31.9: укажите образ `nginx:1.30.7` и выполните `docker compose pull && docker compose up -d`.
</Callout>

<Section title="Способ установки" description="Где работает Remnashop относительно панели Remnawave" icon="Split">

<MethodSwitch same="На одном сервере" separate="На разных серверах" />

<Method only="same">

Nginx работает на том же сервере, что и панель Remnawave.

<Callout type="error">
Nginx уже должен быть установлен и настроен на сервере с панелью Remnawave и остальными компонентами.
</Callout>

</Method>

<Method only="separate">

Remnashop работает на отдельном сервере, без панели Remnawave рядом. Nginx ставится на этот же сервер.

<Callout type="error">
На этом сервере не должно быть установлено других обратных прокси.
</Callout>

</Method>

</Section>

<Section title="Направьте домен на сервер" description="A-запись для домена Remnashop" icon="Globe">

Узнайте IP-адрес вашего сервера. Лучше использовать статический IPv4-адрес.

Теперь направьте доменное имя на этот адрес, например `shop.domain.com` → `127.0.0.1`. Это можно сделать через DNS-провайдера (Cloudflare, Google Cloud и подобные) или через регистратора домена (Namecheap и подобные).

В Cloudflare нужно добавить запись A для IPv4 или AAAA для IPv6. Войдите в [аккаунт Cloudflare](https://dash.cloudflare.com/login) и выберите домен. В левой части страницы откройте `DNS`, затем `Records` и нажмите `Create record`.

Установите `Type` в значение `A`, а `Name` — в `@`.

<Callout type="idea">
Для поддомена впишите в поле `Name` его имя — например, `shop`.
</Callout>

Введите IP-адрес сервера в поле `IPv4 address` и нажмите `Save`. Обновление DNS-записей займёт некоторое время.

<Callout type="idea">
Жёлтое облако (домен проксируется через Cloudflare) и серое облако (не проксируется) работают по-разному. Если Cloudflare хорошо работает в вашем регионе, лучше проксировать домен через него.
</Callout>

![DNS-записи в Cloudflare](/images/cloudflare-dns.webp)

У других DNS-провайдеров интерфейс отличается, но процесс тот же.

</Section>

<Section title="Выпуск сертификата" description="SSL-сертификат для домена Remnashop" icon="ShieldCheck">

<Method only="same">

Выпустите сертификат для домена Remnashop:

```bash title="Выпуск сертификата"
acme.sh --issue --standalone -d 'SHOP_DOMAIN' --key-file /opt/remnawave/nginx/shopdomain_privkey.key --fullchain-file /opt/remnawave/nginx/shopdomain_fullchain.pem --alpn --tlsport 8443
```

</Method>

<Method only="separate">

Самый простой способ — [acme.sh](https://acme.sh/). Сначала установите зависимости:

```bash title="Установка зависимостей"
sudo apt-get install cron socat
```

<Callout type="idea">
Для выпуска сертификата подойдёт любой адрес электронной почты, но лучше использовать действующий.
</Callout>

Замените `EMAIL` на ваш адрес:

```bash title="Установка acme.sh"
curl https://get.acme.sh | sh -s email=EMAIL && source ~/.bashrc
```

Создайте папку для сертификатов:

```bash title="Создание директории"
mkdir -p /opt/remnashop/nginx && cd /opt/remnashop/nginx
```

<Callout type="warn">
Не используйте доменные зоны `.ru`, `.su` и `.рф` — ZeroSSL их не поддерживает.
</Callout>

```bash title="Выпуск сертификата"
acme.sh --issue --standalone -d 'SHOP_DOMAIN' --key-file /opt/remnashop/nginx/shopdomain_privkey.key --fullchain-file /opt/remnashop/nginx/shopdomain_fullchain.pem --alpn --tlsport 8443
```

<Callout type="idea">
Убедитесь, что порт `8443` открыт на сервере — он необходим для выпуска сертификата.
</Callout>

![Успешный выпуск сертификата](/images/issue-cert.webp)

Такой вывод означает, что сертификат выпущен. `acme.sh` будет обновлять его автоматически каждые 60 дней — достаточно, чтобы порт 8443 оставался открытым и свободным.

</Method>

<Callout type="warn">
Замените `SHOP_DOMAIN` на домен Remnashop — значение `APP_DOMAIN`.
</Callout>

</Section>

<Section title="Настройка Nginx" description="Маршруты к контейнерам Remnashop" icon="FileCode">

<Method only="same">

Если Nginx уже настроен, достаточно добавить новые блоки в конфигурационный файл:

```bash title="Редактирование nginx.conf"
cd /opt/remnawave/nginx && nano nginx.conf
```

<Callout type="error">
Не заменяйте существующую конфигурацию полностью — только добавьте в неё блоки для Remnashop.
</Callout>

Добавьте upstream-блоки Remnashop в начало файла:

```nginx title="nginx.conf"
upstream remnawave {
    server remnawave:3000;
}

upstream remnawave-subscription-page {
    server remnawave-subscription-page:3010;
}

upstream remnashop {
    server remnashop:5000;
}

upstream remnashop-telegram {
    server remnashop-telegram:5001;
}
```

Затем добавьте новый блок server в конец файла:

```nginx title="nginx.conf"
server {
    server_name SHOP_DOMAIN;

    listen 443 ssl;
    listen [::]:443 ssl;
    http2 on;

    # лимит тела запроса: медиа для рассылок весят до 50 МБ
    client_max_body_size 64m;

    location = /api/v1/telegram {
        proxy_pass http://remnashop-telegram;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Port $server_port;

        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    location = /metrics {
        return 404;
    }

    location / {
        proxy_pass http://remnashop;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Port $server_port;

        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # SSL Configuration (Mozilla Intermediate Guidelines)
    ssl_protocols          TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305:DHE-RSA-AES128-GCM-SHA256:DHE-RSA-AES256-GCM-SHA384:DHE-RSA-CHACHA20-POLY1305;

    ssl_session_timeout 1d;
    ssl_session_cache shared:MozSSL:10m;
    ssl_session_tickets    off;
    ssl_certificate "/etc/nginx/ssl/shopdomain_fullchain.pem";
    ssl_certificate_key "/etc/nginx/ssl/shopdomain_privkey.key";
    ssl_trusted_certificate "/etc/nginx/ssl/shopdomain_fullchain.pem";

    ssl_stapling           on;
    ssl_stapling_verify    on;
    resolver               1.1.1.1 1.0.0.1 8.8.8.8 8.8.4.4 208.67.222.222 208.67.220.220 valid=60s;
    resolver_timeout       2s;

    # Gzip Compression
    gzip on;
    gzip_vary on;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_buffers 16 8k;
    gzip_http_version 1.1;
    gzip_min_length 256;
    gzip_types
        application/atom+xml
        application/geo+json
        application/javascript
        application/x-javascript
        application/json
        application/ld+json
        application/manifest+json
        application/rdf+xml
        application/rss+xml
        application/xhtml+xml
        application/xml
        application/wasm
        font/eot
        font/otf
        font/ttf
        image/svg+xml
        text/css
        text/javascript
        text/plain
        text/xml;
}
```

</Method>

<Section title="Запуск Nginx" description="Применение конфигурации" icon="Play">

<Method only="same">

Подключите файлы нового сертификата в `docker-compose.yml` Nginx:

```bash title="Редактирование docker-compose.yml"
cd /opt/remnawave/nginx && nano docker-compose.yml
```

```yaml title="docker-compose.yml"
services:
    remnawave-nginx:
        image: nginx:1.30.7
        container_name: remnawave-nginx
        hostname: remnawave-nginx
        volumes:
            - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
            - ./fullchain.pem:/etc/nginx/ssl/fullchain.pem:ro
            - ./privkey.key:/etc/nginx/ssl/privkey.key:ro
            - ./shopdomain_fullchain.pem:/etc/nginx/ssl/shopdomain_fullchain.pem:ro
            - ./shopdomain_privkey.key:/etc/nginx/ssl/shopdomain_privkey.key:ro
        restart: always
        ports:
            - '0.0.0.0:443:443'
        networks:
            - remnawave-network

networks:
    remnawave-network:
        name: remnawave-network
        driver: bridge
        external: true
```

```bash title="Перезапуск контейнера Nginx"
docker compose down && docker compose up -d && docker compose logs -f
```

Чтобы после автоматического продления Nginx подхватывал новый сертификат, сохраните для `acme.sh` команду перезагрузки:

```bash title="Автопродление сертификата"
acme.sh --install-cert -d 'SHOP_DOMAIN' --key-file /opt/remnawave/nginx/shopdomain_privkey.key --fullchain-file /opt/remnawave/nginx/shopdomain_fullchain.pem --reloadcmd "docker exec remnawave-nginx nginx -s reload"
```

<Callout type="idea">
`acme.sh` запомнит эту команду и будет выполнять её после каждого продления.
</Callout>

</Method>
