title: Caddy

---

In this guide we will use Caddy as a reverse proxy to reach Remnashop. We will point a domain name at the server and configure Caddy — the certificates are issued by Caddy itself.

<Callout type="warn">
You need a registered domain name to continue.
</Callout>

<Section title="Installation method" description="Where Remnashop runs relative to the panel" icon="Split">

<MethodSwitch same="Same server" separate="Separate servers" />

<Method only="same">

Caddy runs on the same server as the Remnawave panel.

<Callout type="error">
Caddy must already be installed and configured on the server that runs the Remnawave panel and the other components.
</Callout>

</Method>

<Method only="separate">

Remnashop runs on its own server, without the Remnawave panel next to it. Caddy goes on that same server.

<Callout type="error">
No other reverse proxy may be installed on this server.
</Callout>

</Method>

</Section>

<Section title="Point your domain to the server" description="An A record for the Remnashop domain" icon="Globe">

Check your server's IP address. A static IPv4 address works best.

Now point your domain name at that address, for example `shop.domain.com` → `127.0.0.1`. You can do it through a DNS provider (Cloudflare, Google Cloud and the like) or through your registrar (Namecheap and the like).

With Cloudflare you add an A record for IPv4 or an AAAA record for IPv6. Log in to [your Cloudflare account](https://dash.cloudflare.com/login) and pick the domain. In the left column open `DNS`, then `Records`, and click `Create record`.

Set `Type` to `A` and `Name` to `@`.

<Callout type="idea">
For a subdomain, put its name — `shop`, for instance — in the `Name` field instead.
</Callout>

Enter your server's IP address in the `IPv4 address` field and click `Save`. DNS records take a while to propagate.

<Callout type="idea">
The yellow cloud (domain proxied through Cloudflare) and the grey cloud (domain not proxied) behave differently. If Cloudflare works well in your region, proxying through it is the better choice.
</Callout>

![Cloudflare DNS records](/images/cloudflare-dns.webp)

Other DNS providers look different, but the process is the same.

</Section>

<Section title="Configure the Caddyfile" description="Routes to the Remnashop containers" icon="FileCode">

<Method only="same">

With Caddy already configured, you only add a new site block to the Caddyfile:

```bash title="Edit Caddyfile"
cd /opt/remnawave/caddy && nano Caddyfile
```

<Callout type="error">
Do not replace the existing configuration — only add the Remnashop site block to it.
</Callout>

```text title="Caddyfile"
# PANEL
https://REPLACE_WITH_YOUR_DOMAIN {
        reverse_proxy * http://remnawave:3000
}
# SUBSCRIPTION PAGE
https://SUBSCRIPTION_PAGE_DOMAIN {
        reverse_proxy * http://remnawave-subscription-page:3010
}
# REMNASHOP
https://SHOP_DOMAIN {
        encode
        handle /api/v1/telegram {
                reverse_proxy http://remnashop-telegram:5001
        }
        handle {
                reverse_proxy http://remnashop:5000
        }
}
# CATCH-ALL
:443 {
    tls internal
    respond 204
}
```

</Method>

<Method only="separate">

```bash title="Create Caddyfile"
mkdir -p /opt/remnashop/caddy && cd /opt/remnashop/caddy && nano Caddyfile
```

```text title="Caddyfile"
https://SHOP_DOMAIN {
        encode
        handle /api/v1/telegram {
                reverse_proxy http://remnashop-telegram:5001
        }
        handle {
                reverse_proxy http://remnashop:5000
        }
}
:443 {
    tls internal
    respond 204
}
```

</Method>

<Callout type="warn">
Replace `SHOP_DOMAIN` with the Remnashop domain — the `APP_DOMAIN` value.
</Callout>

<Callout type="idea">
Telegram webhooks go to the `remnashop-telegram` container, everything else to `remnashop`. More in the [overview](/docs/reverse-proxy).
</Callout>

</Section>

<Section title="Start Caddy" description="Applying the configuration" icon="Play">

<Method only="same">

```bash title="Restart the Caddy container"
cd /opt/remnawave/caddy && docker compose down && docker compose up -d && docker compose logs -f
```

</Method>

<Method only="separate">

```bash title="Create docker-compose.yml"
cd /opt/remnashop/caddy && nano docker-compose.yml
```

```yaml title="docker-compose.yml"
services:
    caddy:
        image: caddy:2.9
        container_name: 'caddy'
        hostname: caddy
        restart: always
        ports:
            - '0.0.0.0:443:443'
            - '0.0.0.0:80:80'
        networks:
            - remnawave-network
        volumes:
            - ./Caddyfile:/etc/caddy/Caddyfile
            - caddy-ssl-data:/data
networks:
    remnawave-network:
        name: remnawave-network
        driver: bridge
        external: true
volumes:
    caddy-ssl-data:
        driver: local
        external: false
        name: caddy-ssl-data
```

```bash title="Start Caddy"
docker compose up -d && docker compose logs -f -t
```

</Method>

</Section>

<Section title="Check" description="The dashboard opens on the domain" icon="CircleCheck">

Open `https://shop.domain.com` in your browser — the dashboard page should load. If it does, go back to the [First sign-in](/docs/getting-started/installation#step-8-first-sign-in) step and create the owner account.

</Section>
