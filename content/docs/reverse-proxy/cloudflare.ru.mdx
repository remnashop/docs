Если домены Remnashop или веб-кабинета проксируются через Cloudflare (жёлтое облако), обратный прокси видит вместо клиента адрес Cloudflare. Remnashop берёт IP клиента у обратного прокси, поэтому без настройки ниже все клиенты получают адреса Cloudflare: делят между собой лимиты запросов, а белые списки IP перестают работать.

<Callout type="idea">
С серым облаком (DNS only) эта настройка не нужна.
</Callout>

<Callout type="warn">
Настройка нужна для обоих доменов — и Remnashop, и кабинета: кабинет передаёт Remnashop тот адрес, который получил от обратного прокси.
</Callout>

<Section title="Как это работает" description="Доверие к заголовку CF-Connecting-IP" icon="Route">

Cloudflare передаёт адрес клиента в заголовке `CF-Connecting-IP`. Обратный прокси должен брать адрес из этого заголовка, но только для запросов с адресов Cloudflare: иначе любой клиент, обратившийся к серверу напрямую, подставит в заголовок чужой IP.

Ниже в конфигурациях перечислены диапазоны Cloudflare на момент написания. Актуальные списки: [IPv4](https://www.cloudflare.com/ips-v4) и [IPv6](https://www.cloudflare.com/ips-v6).

</Section>

<Section title="Caddy" description="trusted_proxies и client_ip_headers" icon="Server">

Добавьте блок глобальных опций в самое начало Caddyfile:

```text title="Caddyfile"
{
	servers {
		trusted_proxies static 173.245.48.0/20 103.21.244.0/22 103.22.200.0/22 103.31.4.0/22 141.101.64.0/18 108.162.192.0/18 190.93.240.0/20 188.114.96.0/20 197.234.240.0/22 198.41.128.0/17 162.158.0.0/15 104.16.0.0/13 104.24.0.0/14 172.64.0.0/13 131.0.72.0/22 2400:cb00::/32 2606:4700::/32 2803:f800::/32 2405:b500::/32 2405:8100::/32 2a06:98c0::/29 2c0f:f248::/32
		client_ip_headers CF-Connecting-IP
	}
}
```

<Callout type="warn">
Если в Caddyfile уже есть блок глобальных опций (`{ ... }` в начале файла), добавьте `servers` в него, а не вторым блоком.
</Callout>

Затем в каждый `reverse_proxy` сайтов Remnashop и кабинета добавьте строку `header_up X-Forwarded-For {client_ip}`:

```text title="Caddyfile"
https://SHOP_DOMAIN {
        encode
        handle /api/v1/telegram {
                reverse_proxy http://remnashop-telegram:5001 {
                        header_up X-Forwarded-For {client_ip}
                }
        }
        handle {
                reverse_proxy http://remnashop:5000 {
                        header_up X-Forwarded-For {client_ip}
                }
        }
}
https://CABINET_DOMAIN {
        encode
        reverse_proxy http://remnashop-cabinet:80 {
                header_up X-Forwarded-For {client_ip}
        }
}
```

<Callout type="idea">
Без `header_up` Caddy дописывает в конец `X-Forwarded-For` адрес Cloudflare, а Remnashop читает именно последний адрес.
</Callout>

</Section>

<Section title="Nginx" description="Модуль real_ip" icon="Server">

Добавьте в начало `nginx.conf`, рядом с блоками `upstream`:

```nginx title="nginx.conf"
# Cloudflare: адрес клиента из CF-Connecting-IP, только от адресов Cloudflare
set_real_ip_from 173.245.48.0/20;
set_real_ip_from 103.21.244.0/22;
set_real_ip_from 103.22.200.0/22;
set_real_ip_from 103.31.4.0/22;
set_real_ip_from 141.101.64.0/18;
set_real_ip_from 108.162.192.0/18;
set_real_ip_from 190.93.240.0/20;
set_real_ip_from 188.114.96.0/20;
set_real_ip_from 197.234.240.0/22;
set_real_ip_from 198.41.128.0/17;
set_real_ip_from 162.158.0.0/15;
set_real_ip_from 104.16.0.0/13;
set_real_ip_from 104.24.0.0/14;
set_real_ip_from 172.64.0.0/13;
set_real_ip_from 131.0.72.0/22;
set_real_ip_from 2400:cb00::/32;
set_real_ip_from 2606:4700::/32;
set_real_ip_from 2803:f800::/32;
set_real_ip_from 2405:b500::/32;
set_real_ip_from 2405:8100::/32;
set_real_ip_from 2a06:98c0::/29;
set_real_ip_from 2c0f:f248::/32;
real_ip_header CF-Connecting-IP;
```

Больше ничего менять не нужно: `X-Real-IP $remote_addr` и `X-Forwarded-For $proxy_add_x_forwarded_for` из конфигурации Remnashop и кабинета уже передают исправленный адрес.

</Section>

<Section title="Traefik" description="Штатной поддержки нет" icon="Server">

<Callout type="warn">
Traefik не умеет брать адрес клиента из `CF-Connecting-IP`. С `forwardedHeaders.trustedIPs` он сохраняет входящий `X-Forwarded-For`, но дописывает в конец адрес Cloudflare, а Remnashop читает именно последний адрес.
</Callout>

Если домены проксируются через Cloudflare, используйте Caddy или Nginx. Другой вариант — сторонний плагин Traefik, который переписывает `X-Forwarded-For` из `CF-Connecting-IP`; такие плагины не входят в Traefik, и мы их не проверяли.

</Section>

<Section title="Проверка" description="Адрес клиента в Remnashop" icon="CircleCheck">

Перезапустите обратный прокси и проверьте адрес, который видят Remnashop и кабинет. Узнать свой IP можно, например, на [ifconfig.me](https://ifconfig.me).

**Remnashop.** Откройте в панели управления документацию API и найдите в логе строку `Docs access granted to IP`:

```bash title="Лог Remnashop"
cd /opt/remnashop && docker compose logs remnashop | grep "Docs access"
```

**Кабинет.** Откройте кабинет в браузере и посмотрите первый адрес в строках access-лога:

```bash title="Лог кабинета"
cd /opt/remnashop/cabinet && docker compose logs --tail 5
```

В обоих случаях должен быть ваш IP, а не адрес из диапазонов Cloudflare.

</Section>
