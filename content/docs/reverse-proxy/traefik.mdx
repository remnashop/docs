title: Traefik
icon: Server
---

In this guide we will use Traefik as a reverse proxy to reach Remnashop. We will point a domain name at the server and configure Traefik — the certificates are issued by Traefik itself through Let’s Encrypt.

<Callout type="warn">
You need a registered domain name to continue.
</Callout>

<Section title="Installation method" description="Where Remnashop runs relative to the panel" icon="Split">

<MethodSwitch same="Same server" separate="Separate servers" />

<Method only="same">

Traefik runs on the same server as the Remnawave panel.

<Callout type="error">
Traefik must already be installed and configured on the server that runs the Remnawave panel and the other components.
</Callout>

</Method>

<Method only="separate">

Remnashop runs on its own server, without the Remnawave panel next to it. Traefik goes on that same server.

<Callout type="error">
No other reverse proxy may be installed on this server.
</Callout>

</Method>

</Section>

<Section title="Point your domain to the server" description="An A record for the Remnashop domain" icon="Globe">

Check your server's IP address. A static IPv4 address works best.

Now point your domain name at that address, for example `shop.domain.com` → `127.0.0.1`. You can do it through a DNS provider (Cloudflare, Google Cloud and the like) or through your registrar (Namecheap and the like).

With Cloudflare you add an A record for IPv4 or an AAAA record for IPv6. Log in to [your Cloudflare account](https://dash.cloudflare.com/login) and pick the domain. In the left column open `DNS`, then `Records`, and click `Create record`.

Set `Type` to `A` and `Name` to `@`.

<Callout type="idea">
For a subdomain, put its name — `shop`, for instance — in the `Name` field instead.
</Callout>

Enter your server's IP address in the `IPv4 address` field and click `Save`. DNS records take a while to propagate.

<Callout type="idea">
The yellow cloud (domain proxied through Cloudflare) and the grey cloud (domain not proxied) behave differently. If Cloudflare works well in your region, proxying through it is the better choice.
</Callout>

![Cloudflare DNS records](/images/cloudflare-dns.webp)

Other DNS providers look different, but the process is the same.

</Section>

<Section title="Configure Traefik" description="The static configuration and the container" icon="Settings">

<Method only="same">

With Traefik already configured, move on to the next step: the Remnashop routes go into a file of their own.

</Method>

<Method only="separate">

```bash title="Create docker-compose.yml"
mkdir -p /opt/remnashop/traefik && cd /opt/remnashop/traefik && nano docker-compose.yml
```

```yaml title="docker-compose.yml"
services:
    traefik:
        image: traefik:latest
        container_name: traefik
        restart: unless-stopped
        security_opt:
            - no-new-privileges:true
        networks:
            - remnawave-network
        ports:
            - '0.0.0.0:80:80'
            - '0.0.0.0:443:443'
        environment:
            - TZ=UTC
        volumes:
            - /var/run/docker.sock:/var/run/docker.sock:ro
            - ./traefik.yml:/traefik.yml:ro
            - ./letsencrypt:/letsencrypt
            - ./config:/config:ro
            - ./logs:/var/log/traefik
networks:
    remnawave-network:
        name: remnawave-network
        driver: bridge
        external: true
```

```bash title="Create traefik.yml"
cd /opt/remnashop/traefik && nano traefik.yml
```

<Callout type="warn">
Replace `REPLACE_WITH_YOUR_EMAIL` with your email address.
</Callout>

```yaml title="traefik.yml"
api:
  dashboard: true
  debug: true
entryPoints:
  http:
    address: ":80"
    http:
      redirections:
        entryPoint:
          to: https
          scheme: https
  https:
    address: ":443"
serversTransport:
  insecureSkipVerify: true
providers:
  file:
    directory: /config
    watch: true
certificatesResolvers:
  letsencrypt:
    acme:
      email: REPLACE_WITH_YOUR_EMAIL
      storage: /letsencrypt/acme.json
      httpChallenge:
        entryPoint: http
log:
  level: "INFO"
  filePath: "/var/log/traefik/traefik.log"
accessLog:
  filePath: "/var/log/traefik/access.log"
```

</Method>

</Section>

<Section title="Remnashop routes" description="The dynamic configuration file" icon="FileCode">

<Method only="same">

```bash title="Create remnashop.yml"
cd /opt/remnawave/traefik/config && nano remnashop.yml
```

</Method>

<Method only="separate">

```bash title="Create remnashop.yml"
mkdir -p /opt/remnashop/traefik/config && cd /opt/remnashop/traefik/config && nano remnashop.yml
```

</Method>

<Callout type="warn">
Replace `SHOP_DOMAIN` with the Remnashop domain — the `APP_DOMAIN` value.
</Callout>

```yaml title="remnashop.yml"
http:
  routers:
    remnashop-telegram:
      rule: "Host(`SHOP_DOMAIN`) && Path(`/api/v1/telegram`)"
      entrypoints:
        - https
      tls:
        certResolver: letsencrypt
      service: remnashop-telegram
    remnashop:
      rule: "Host(`SHOP_DOMAIN`)"
      entrypoints:
        - https
      tls:
        certResolver: letsencrypt
      service: remnashop

  services:
    remnashop-telegram:
      loadBalancer:
        servers:
          - url: "http://remnashop-telegram:5001"
    remnashop:
      loadBalancer:
        servers:
          - url: "http://remnashop:5000"
```

<Callout type="idea">
Telegram webhooks go to the `remnashop-telegram` container, everything else to `remnashop`. More in the [overview](/docs/reverse-proxy).
</Callout>

</Section>

<Section title="Start Traefik" description="Applying the configuration" icon="Play">

<Method only="same">

Traefik watches the `config` directory and picks up `remnashop.yml` on its own — no restart needed.

</Method>

<Method only="separate">

```bash title="Start Traefik"
cd /opt/remnashop/traefik && docker compose up -d && docker compose logs -f -t
```

</Method>

</Section>

<Section title="Check" description="The dashboard opens on the domain" icon="CircleCheck">

Open `https://shop.domain.com` in your browser — the dashboard page should load. If it does, go back to the [First sign-in](/docs/getting-started/installation#step-8-first-sign-in) step and create the owner account.

</Section>
